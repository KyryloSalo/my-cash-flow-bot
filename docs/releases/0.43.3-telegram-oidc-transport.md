## Shipped scope and cause

Telegram provider responses can contain gzip bytes. Treating compressed JWKS or token JSON as raw UTF-8 fails decoding and can surface as `telegram_oidc_token_invalid`. The shared decoder now decompresses responses identified by the gzip header or magic bytes before parsing JSON. The custom JWKS transport retains PyJWT signature/key validation and caching and rejects redirects. Safe error logs emit exception types, not tokens, claims, response bodies or credential-bearing URLs. State, PKCE, nonce, supported signing algorithms and replay protection are not relaxed.

The runtime also contains the preceding reviewed browser-entry change: bot buttons use the public HTTPS `/app/login/` entry, which requires the user to confirm their own identity through Telegram OIDC. Ordinary entry no longer needs internal signed-link issuance. Legacy signed-link routes remain compatible; mobile external-browser handoff remains separate from authentication.
