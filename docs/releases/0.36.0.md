## Shipped behavior

- Added the shared Postgres-backed capture foundation: device pairing, encrypted credentials, idempotent ingest, persistent inbox, review state, revision checks, and explicit confirmation before one transaction is created.
- Added the PWA capture inbox and edit/review flow. Ingest never writes a financial transaction automatically.
- Added the Android notification-listener candidate, persistent delivery queue, strict pairing/trusted-origin handling, notification-instance event identity, and repair-required handling for revoked credentials.
- Account deletion now removes capture credentials, events, inbox rows, and related pending data atomically before deleting the user.
- Rollout is fail-closed: capture flags remain `false` by default and access additionally requires an allowlisted user. No bank package is enabled merely by this deployment.
- Automatic iOS capture is not included. iPhone users remain on the manual flow until physical-device acceptance is completed.

## Verification and release gates

## Remaining device gates

- No Android user or bank package may be allowlisted until a physical Android test verifies installation, pairing, notification permission, a real supported-bank notification, persistent inbox delivery, PWA review, and exactly-one confirmed transaction.
- Automatic iOS capture remains disabled until physical iPhone acceptance. This does not block the already deployed default-off shared foundation or the Android internal candidate.

This release publishes the production-safe foundation and internal Android candidate. It does not claim that automatic capture is enabled for production users.
