## Shipped contract

Confirmed payment is not itself active access. Activation requires usable authorization and the reserved entitlement; recovery applies that same payment exactly once, prefers the latest valid rebind mandate, and preserves manual access, trial consumption, refunded/revoked payments and superseded mandates. Duplicate invoices and consumed consent are blocked before provider invocation. Reconciliation uses the existing beat task with persisted exponential cooldown and at most eight attempts; this is activation recovery, not permission for another debit.

`access.activation_state` is `active`, `not_started`, `payment_pending` or `paid_activation_pending`. `recommended_action=continue_payment` is only for an unpaid existing invoice with an action URL; pending recovery otherwise uses `check_activation`. Consumed consent returns `billing_consent_consumed` before provider calls; a definitive failure permits a separately consented retry. Signed return refreshes the fresh-browser PWA state and never equates paid with active.

Financial writes retain explicit confirmation. Existing offer identity, 30/90-day trial rules, 1 UAH binding and 499 UAH renewal terms are unchanged. Rebinding must not manufacture a fresh trial or extend a consumed entitlement.
