## Root cause and shipped fix

The server creates immutable offer IDs in the form `partner_link:<positive integer>`. Funnel validation accepted only slug characters, so its rejection of the colon raised `offer_variant is invalid` inside the billing consent path. The same mismatch affected consent acceptance, invoice attachment and paid-consent event recording.

Only `offer_variant` now accepts the bounded numeric partner-offer format. All other fields retain the existing slug validation. IDs are not rewritten; arbitrary colon values, zero/leading-zero/non-numeric/oversized IDs and injection-shaped values remain rejected. No account reset, replacement Telegram identity, bonus rewrite, or payment-provider bypass was introduced.
