## Shipped behavior

- Credit creation/onboarding explicitly using `balance_input_mode=available_credit` converts bank-available funds to canonical net balance: available `100000` with limit `300000` means balance `-200000`, debt `200000`, own funds `0` and available credit `100000`.
- Omitted/legacy net input preserves existing signed-balance semantics. Existing accounts are not automatically recalculated. Editing and balance corrections keep their confirmation boundaries.
- Interest is a percentage rate, retaining decimal precision; the preview uses actual debt (for example `200000` at `3.5%` gives `7000`), not own funds or the full limit.
- Billing recovery from PR #89 is preserved. Goals runtime is unchanged: funded remains open, spent/completed are closed, and progress remains actual, including overfunding. The stale goals test now exercises production helpers; all frontend tests are enforced in required CI.
- Transfers remain transfers, cross-currency transfers require FX, and financial writes require confirmation.
