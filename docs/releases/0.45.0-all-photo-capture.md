## Shipped scope

The PWA captures supported receipt photos before recognition normalization, including preprocessing and provider failures. Telegram photo and image-document inputs use the same original-file capture path. Originals are queued after commit as Telegram documents for configured administrators without recompression. Captions contain bounded source/outcome context, not raw provider responses.

Delivery is durably pausable, uses bounded retries and a direct-PostgreSQL session mutex, and is at-least-once rather than exactly-once. Recognition outcome delivery waits up to two minutes and recovery can send a `pending` result. No ledger write occurs before explicit confirmation.

Private storage has a 1 GiB hard quota, 10 MiB per-file limit, private permissions, and at-most-seven-day retention. Account deletion removes private capture metadata/files and pending references after commit; already-delivered Telegram copies are not retracted. Quota, storage, and notification failures do not create financial writes or turn recognition into a request failure.

The release also includes durable outbox pause semantics, retry exhaustion/dead-letter handling, deletion cleanup, account deletion integration, and exact internal HTTP TLS exemption handling. The feature is not an exactly-once delivery system.
